## Problem

`scripts/check-key-drift.sh`'s `load_json()` parsed both core's en.json and
this pack's de.json with plain `json.load`, which silently keeps only the
LAST of a duplicated top-level key. Real incident: two lanes independently
closed `universal-till`#941's `lang-pack-drift` gap (this pack's own PR #206,
and PR #204 from a concurrent ut-docs#1841 cycle), each inserting the same
five `orders.view.*`/`pos.toast.receipt_*` keys at a different point in
`locales/de.json`. Git merged both non-conflicting insertions cleanly. The
guard reported "0 drift, 0 orphans" against a file that actually defined
five keys twice. Filed as ut-docs#1872 (a duplicate-key check has to read
the raw text, not the parsed object) after a first attempt at fixing the
five duplicates (PR #207, "Remove five duplicated locale keys") turned out
not to hold — the current `main` still carried all five, plus two more
(`elevation.summary.backup_restore`/`data_customer_erase`, from a separate,
still-open incident, ut-docs#1876) that arrived the same way. Verified
directly against `main` while starting this card: `locales/de.json` had 7
real duplicate keys live, right now.

## What shipped

- `scripts/check-key-drift.sh`'s `load_json(path, label)`: now reads the
  raw key/value pair list via `object_pairs_hook`, and fails (naming the
  file and every duplicated key) before returning, for BOTH the core en.json
  load and the de.json load — same hard-failure class as invalid JSON.
- `scripts/check-key-drift.test.sh`: two new cases (search "ut-docs#1872")
  — a duplicate key in de.json, and a duplicate key in the fetched core
  en.json — each asserting both the failure and that the report names the
  right file and key.
- `locales/de.json`: the 7 live duplicates removed. Six were resolved by
  merit rather than position (kept the copy matching this file's own
  established terminology — "Backup-Ordner" over "Sicherungsordner" to
  match the sibling `backup_now` key's wording, GDPR-correct
  "personenbezogene Daten" over "persönliche Daten" for a data-erasure
  notice, "erstatten" (refund) over "Retoure" (return) to match the English
  source's "Refund instead") — one pair per key, no third copy anywhere.
- `manifest.json`: version 1.1.34 -> 1.1.35 — a locale-only content fix is
  invisible to the fleet without a bump (the marketplace serves the
  released/tagged build; established precedent, PR #207's own commit
  message).
