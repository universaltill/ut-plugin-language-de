## Hand check of meaning (all 68 keys)

Behaviour cross-checked against `claim.md` and `internal/pages/move_approval.go`:
a manager/admin approves or declines on the till with a PIN, three wrong
PINs decline, the till keeps selling and nothing is wiped; the sales
history is merged into the other shop's cloud account. Every German string
says exactly that — no "löschen"/"übertragen"-style false meaning, every
"Nothing changed" is rendered ("Es hat sich nichts geändert" / "An dieser
Kasse hat sich nichts geändert"), the destructive consequence in
`settings.move.warning` (history goes to the other account; support never
asks) is stated as in English.

Register and terminology: formal Sie throughout; `Kasse` for till,
`Geschäft` for shop (the pack's dominant term; "Laden" occurrences in the
file are mostly the verb *laden*), `koppeln` for pair, `Inhaber` for owner,
`Manager oder Admin` (both `Admin` and `Administrator` already occur;
`Admin-PIN` is the neighbour), `genehmigen`/`ablehnen` for approve/decline,
`Umzug`/`umziehen` for move — the pack already used "umzieht" for a cloud
migration (`designer.receipt.tracking_qr_needs_cloud`), so the term is
consistent, and it is unambiguous against `verschieben` (used for moving
items/categories within the till). `agent.value.on` "An" matches the
neighbour "Immer an". Placeholders: `%s` in `notice_pending` is a shop
name per `en.meta.json`, so "%s möchte … in sein Geschäft umziehen" reads
correctly.

Author's claimed fix verified: `settings.enrol.pair_replace_body` says
"Verkäufe, Produkte und Einstellungen bleiben auf dieser Kasse" (products,
not Artikel), matching `settings.move.warning` in the same batch.
